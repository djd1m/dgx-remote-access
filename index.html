Доступ к DGX и с DGX.
Без обрывов.

Надёжный удалённый доступ к Spark, Split-VPN для Claude Code (только нужная консоль через exit) и локальные модели — в одной инструкции. Уровни минимальный → оптимальный → максимальный, с настройками на DGX, роутере Keenetic и облачных VPS.

Архитектура и узлы

Три независимые плоскости: вход к DGX, выход с DGX к Claude, локальные модели. Две VPN не конфликтуют — exit Claude живёт в отдельном network namespace и физически не может увести дефолтный маршрут (а значит, не уронит входящий доступ).

Минимальный уровень

◷ ~1 час
2.1Keenetic: статический IP провайдера + фиксированный IP сервера⏱ 5м
  • Вход в роутер: http://my.keenetic.net (или 192.168.1.1).
  • Публичный IP (не CGNAT): Системный монитор → панель «Интернет» → IP-адрес, сравни с curl ifconfig.me с любого устройства сети. Купленный статический IP — это он. Не совпало или адрес из 10/172.16/192.168/100.64 → серый IP/CGNAT, входящий проброс не сработает.
  • Фиксированный IP для сервера (подключение по Wi-Fi роли не играет): Список устройств → выбери сервер → Зарегистрировать и включить «Постоянный IP-адрес» → 192.168.1.50. Работает одинаково для Wi-Fi и кабельных клиентов.
  • (Опционально, belt-and-suspenders) статика на самом сервере через NetworkManager — держится независимо от роутера. Достаточно регистрации выше; адрес должен быть тот же.
опционально: статика на сервере (nmcli)
nmcli connection show --active                       # узнать имя WiFi-профиля
nmcli connection modify "<wifi-profile>" ipv4.method manual \
  ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1 ipv4.dns "1.1.1.1 8.8.8.8"
nmcli connection up "<wifi-profile>"
2.2DGX: усиление SSH⏱ 10м
на клиенте → потом на DGX
# КЛИЕНТ: ключ + копирование (пока по паролю)
ssh-keygen -t ed25519 -C "dgx-access"
ssh-copy-id cloud@192.168.1.50
ssh cloud@192.168.1.50   # проверь вход ПО КЛЮЧУ

# DGX: закрутить гайки
sudo tee /etc/ssh/sshd_config.d/99-hardening.conf >/dev/null <<'EOF'
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
AllowUsers cloud
MaxAuthTries 3
EOF
sudo systemctl restart ssh
Порядок важен
Сначала убедись, что ключ работает, ПОТОМ отключай пароль — иначе закроешь себе доступ.
Альтернатива без VPN: прямой проброс SSH на Keenetic
Сетевые правила → Переадресация → Добавить правило. Вход: твоё интернет-подключение (провайдер). Выход: сервер 192.168.1.50 (выбери из списка устройств). Протокол: TCP. Открыть порт (внешний) 49222 → переадресовать на порт (внутренний) 22. Не пробрасывай внешний 22 — на нестандартном порту в разы меньше брутфорса. Keenetic сам открывает фаервол для проброшенного порта. По возможности заполни «Разрешённые адреса источника» своим IP. Заход извне: ssh -p 49222 cloud@<статический_IP>. Пароль отключён, на сервере fail2ban (уровень «максимальный») — прямой SSH приемлем. Но рекомендуемый путь — WireGuard-сервер на роутере (шаг 2.3): тогда наружу не торчит вообще ничего, а SSH ходит внутри туннеля.
2.3Keenetic: WireGuard-сервер на роутере⏱ 15м

Туннель терминируется на самом роутере: на сервере наружу не открыто ничего, проброс портов не нужен, а после подключения доступна вся домашняя сеть (DGX + любые устройства). Рекомендуемый путь для Keenetic.

  • Компонент: Общие настройки → Обновления и компоненты → Изменить набор компонентов → включи WireGuard. Обнови KeeneticOS до актуальной (в свежих версиях есть мастер «WireGuard VPN-сервер»).
  • Подключение: Интернет → Другие подключения → WireGuard → Добавить. Сгенерируй пару ключей, адрес интерфейса 10.50.0.1/24, порт прослушивания 51820.
  • Пир (ноут/телефон): вставь публичный ключ клиента, его Allowed IPs = 10.50.0.2/32. Скопируй публичный ключ роутера для клиентского конфига.
  • Доступ к LAN (ключевой момент): в настройках WG-подключения выключи «Использовать для выхода в интернет» и разреши трафик из 10.50.0.0/24 к домашнему сегменту (в зависимости от версии KeeneticOS — регистрация интерфейса в домашнем сегменте или правило фаервола WG→LAN).
клиентский конфиг (ноут/телефон)
[Interface]
PrivateKey = <client_private_key>
Address = 10.50.0.2/32

[Peer]
PublicKey = <keenetic_public_key>
Endpoint = <ДОМАШНИЙ_СТАТИЧЕСКИЙ_IP>:51820
AllowedIPs = 192.168.1.0/24        # вся домашняя сеть, включая сервер
PersistentKeepalive = 25
Готово
Поднимаешь туннель → ssh cloud@192.168.1.50. SSH никуда наружу не торчит. В мобильном приложении Keenetic пир добавляется в пару кликов с генерацией QR-кода. Проброс портов на роутере не требуется — он сам принимает UDP 51820.
Альтернатива: терминировать WireGuard на сервере (если не доверяешь прошивке роутера или нужен zero-trust строго к одному хосту)

Роутер только пробрасывает UDP-порт, а туннель завершается на сервере. Больше движущихся частей, наружу проброшен порт, доступ — только к серверу.

сервер: ключи + интерфейс
sudo apt update && sudo apt install -y wireguard
umask 077
wg genkey | sudo tee /etc/wireguard/in_server.key | wg pubkey | sudo tee /etc/wireguard/in_server.pub
/etc/wireguard/wg-in.conf (сервер)
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = <in_server.key>

[Peer]                           # твой ноут/телефон
PublicKey = <client_public_key>
AllowedIPs = 10.10.0.2/32
запуск + клиентский конфиг
# сервер:
sudo systemctl enable --now wg-quick@wg-in && sudo wg show

# КЛИЕНТ (Endpoint = домашний статический IP):
[Interface]
PrivateKey = <client_private_key>
Address = 10.10.0.2/32
[Peer]
PublicKey = <in_server_public_key>
Endpoint = <ДОМАШНИЙ_СТАТИЧЕСКИЙ_IP>:51820
AllowedIPs = 10.10.0.1/32
PersistentKeepalive = 25
Keenetic: проброс на сервер
Сетевые правила → Переадресация → Добавить правило: вход — интернет-подключение; выход — сервер 192.168.1.50; протокол UDP; внешний 51820 → внутренний 51820. Больше ничего наружу.
2.4VPS Нидерланды (adminvps): WireGuard-exit⏱ 15м
на VPS Ubuntu
sudo apt update && sudo apt install -y wireguard
umask 077
wg genkey | sudo tee /etc/wireguard/server.key | wg pubkey | sudo tee /etc/wireguard/server.pub
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-wg.conf && sudo sysctl --system
ip route   # узнай внешний интерфейс (eth0 / ens3 / ...)
/etc/wireguard/wg0.conf (VPS, замени eth0)
[Interface]
Address = 10.7.0.1/24
ListenPort = 51820
PrivateKey = <server.key>
PostUp   = iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE; iptables -A FORWARD -i wg0 -j ACCEPT; iptables -A FORWARD -o wg0 -j ACCEPT
PostDown = iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE; iptables -D FORWARD -i wg0 -j ACCEPT; iptables -D FORWARD -o wg0 -j ACCEPT

[Peer]                           # DGX (netns claude-vpn)
PublicKey = <dgx_client.pub>
AllowedIPs = 10.7.0.2/32
поднять + открыть порт
sudo systemctl enable --now wg-quick@wg0 && sudo wg show
# открой UDP 51820 в фаерволе VPS и в панели adminvps

Авто-NAT-traversal, мультидевайс, заодно транспорт для будущего флота агентов.

3.2xrdp (GUI, hardened)
DGX
sudo apt install -y xrdp && sudo adduser xrdp ssl-cert
sudo sed -i 's/^port=3389/port=3389\naddress=127.0.0.1/' /etc/xrdp/xrdp.ini
sudo systemctl enable --now xrdp
sudo tee /etc/polkit-1/rules.d/02-allow-colord.rules >/dev/null <<'EOF'
polkit.addRule(function(action, subject){
  if (action.id.indexOf("org.freedesktop.color-manager.")===0){ return polkit.Result.YES; }
});
EOF

Заход: ssh -L 3389:localhost:3389 cloud@<wg/netbird-ip> → RDP на localhost:3389. Чёрный экран на GNOME → sudo apt install -y xfce4 && echo xfce4-session > ~/.xsession.

DGX

4.1Self-hosted NetBird на cloud.ru (РФ)

Координатор и метаданные сети — в РФ-контуре. Unified Server Binary (management+signal+relay, v0.65+) + домен/TLS + встроенный Zitadel.

агенты узлов → свой координатор
sudo netbird up --management-url https://<твой-netbird-домен>
Не «1 час»
Self-host с IdP — отдельная задача, поэтому максимальный уровень. Точные домен/TLS/env — из официального getting-started NetBird.
4.2SGLang вместо Ollama (флот + RAG)

Проверки и грабли

  • Split работает? В netns curl ifconfig.me = IP NL-VPS; в host = домашний IP.
  • CGNAT: IP в Keenetic (Системный монитор → Интернет) ≠ curl ifconfig.me → серый IP, inbound-проброс не сработает.
  • SSH закрылся после PasswordAuthentication no → ключ не был проверен; чини из локальной консоли.
  • Claude Code + SOCKS нельзя (только HTTP/HTTPS) → для лёгкой альтернативы нужен HTTP-CONNECT-прокси на NL-VPS + export HTTPS_PROXY=....
  • vopono на ARM64 → собирается из исходников; нужен wireguard-tools.
  • wg-quick не умеет netns (ручной вариант) → wg setconf без Address/DNS/MTU.
